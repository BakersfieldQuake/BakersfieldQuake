# macOS FPS profile — 2026-11-26

Machine: M2 Max, macOS 27.0.1, GL 4.1 Metal-91.7 (Apple GL-on-Metal). Engine: installed BAKOQUAKE.app v1.91
(Zircon GiggleHacks@66bcfa2, stripped). Settings: Rob's `config.cfg` + picker `bq_launch_video.cfg` (2560x1440
borderless, preset normal, `vid_samples 4`, bloom, dlight shadows). Benchmark: `timerefresh` x3 (`+vid_vsync 0
+cl_maxfps 0`), isolated `-userdir`, plus `timedemo intro.dem`.

## Measured

- `timedemo intro.dem`, real settings: 70.5 fps avg, one-second min/avg/max 50/74/117.
- `sample` of the main thread during timerefresh on bakersfielddowntown: 3249 of 4370 samples (74%) inside
  `glBufferSubData` -> `gldBufferSubData` -> `GLDContextRec::flushResource` -> `flushContext` ->
  `-[_MTLCommandQueue submitCommandBuffer:]`. Every sub-buffer update submits a Metal command buffer.
  With `vid_samples 0` it is still 1988 of 4478 (44%), so it is per-call cost, not only pixel work.
  On `start`: 48% in glBufferSubData, 23% in `CGLFlushDrawable`.
- The only `subdata` caller is `R_BufferData_Store` (gl_rmain.c:3934): all dynamic vertex/index/uniform data
  (UI, particles, decals, animcache, dynamic batches, immediate-mode meshes).
- `source/darkplaces-macos-mapbufferrange.patch` (written 2026-11-01 for upstream DP) was never carried into the
  Zircon build: 66bcfa2 still calls `qglBufferSubData`. It applies cleanly to 66bcfa2 (offsets only) and
  `clang -fsyntax-only` passes on gl_backend.c and vid_shared.c.
- `vid_samples N` does more than MSAA in Zircon: `R_Bloom_StartFrame` (gl_rmain.c:5647, "Baker: Difference from DP
  Beta") scales the offscreen view target by `sqrt(vid.samples)`, independent of `r_bloom`. `vid_samples 4` at
  2560x1440 renders the 3D view at 5120x2880.

## Open / unverified

- Buffer sizes. Rob's config has `r_buffermegs_vertex 128` (Zircon doubles and archives it on overflow;
  `R_BufferData_Store` re-specifies the whole buffer with `glBufferData(NULL, size)` at offset 0). Defaults helped
  on `start` (24 -> 68) and were mixed on downtown (42 -> 52; with `vid_samples 1` 110 -> 79). Run-to-run
  noise was large (`start_base` 24 vs 60 on repeats; Rob was using the machine). Not concluded.
- Patch effect: not benchmarked. The 2026-11-01 log (`docs/benchmark-2026-11-01.log`) shows 24.6 -> 63.3 fps on
  old DP, but run 2 (unpatched, reliefmapping off) also gave 63, so that is weak evidence.
- Early matrix runs were contaminated: the engine saves `+cvar` overrides into the test `config.cfg` on quit
  (`r_viewscale 0.5`, safemode leftovers). Only the table above is clean.
- Shaders compile lazily mid-game (`GLSL shader ... compiled` lines during play). Hitches on first use of a
  permutation?

## Changes

- Engine: commit `1641494` on top of 66bcfa2 in BakersfieldQuake/zircon-darkplaces (the patch, with the map path
  under `#ifdef __APPLE__`; other platforms keep `glBufferSubData`).
- `source/mac/build_app.sh` builds from BakersfieldQuake/zircon-darkplaces at `1641494` instead of the GiggleHacks
  fork (and re-points `origin` on a cached clone). `ZIRCON_REF` is in `mac-inputs`, so this ships a new DMG.
