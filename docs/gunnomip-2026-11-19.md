# No mipmaps for three gun view models (`zz_gunnomip.pk3`), 2026-11-19

Follow-up to `docs/gunframes-atlas-2026-11-18.md`. That atlas pack saved texture memory but, with the fs_dircache
engine, no load time, for 92.1 MB of download, so it is not shipping. Its memory saving came from one change that
needs no atlases: the dookie, green-jar and robhead-drone view models stop building mipmaps. This pack makes only
that change. It is 56.5 KB.

**Status:** builder and CI step written and tested locally, and committed. Not installed in the game folder and not
deployed. It ships with the first release built after the commit is on GitHub main. That release changes shaders,
so give it a look in game.

## What it is

- Builder: `source/mm_tools/build_gunnomip_pk3.py <bakersfield.pk3> [out.pk3]`. Standard library only.
- It copies `scripts/dookievm.shader` (114 shaders), `scripts/greenjarvm.shader` (112) and `scripts/rh_dronevm.shader`
  (224: 112 card frames and 112 head frames) from `bakersfield.pk3` and adds `nomipmaps` after `cull none` in every
  shader, where `milkyvm.shader` and `picklevm.shader` already have it. It adds one comment line at the top of each
  file and changes nothing else. The builder checks that by removing the added lines and comparing the result
  with the original file.
- The overlay's file replaces the base file of the same name. The engine loads each shader file name once, from the
  highest-priority pack, so the base copies are not read.
- **Reproducible:** two builds gave the same sha256,
  `67b55779e1f50692521647417d8630fc809237a67a7f2deba98235ecff7cebc4` (56,534 bytes). Entries are sorted, dated
  1980-01-01, with fixed attributes, and stored rather than deflated, so the bytes don't depend on the zlib
  version either.
- **Not together with `zz_gunframes.pk3`.** Both replace these three files. `zz_gunnomip` sorts later and would
  override the atlas shaders, which already say `nomipmaps`. The package check fails if both are present.
  `docs/gunframes-atlas/build-zip-ci-step.patch` would have to drop this pack before it could be used.

## Result (soi6, Windows release layout, fs_dircache engine)

Four alternating before/after pairs, `loadtime.py <tag> soi6 --quiet --basedir G:\Quake\_bq_perf_base
--same-userdir`, with `config.cfg` reset from `lan\seed_config.cfg` before each run:

| | before | after |
|---|---|---|
| gun frames loaded with mipmaps (`dvm_`, `gjvm_`, `rh_drone_*`) | 450 | 0 |
| texture memory | 1,819 MB | 1,751 MB (**−68 MB**) |
| peak commit | 3,298 to 3,355 MB | 3,193 to 3,213 MB (**about −110 MB**) |
| load (s) | 7.1, 7.6, 6.7, 6.7 (mean 7.0) | 6.6, 7.3, 6.5, 6.6 (mean 6.75) |

- This saves more memory than the atlas pack (−52 MB), because atlases carry gutters and empty cells.
- Every pair loaded a little faster (0.5, 0.3, 0.2, 0.1 s): the engine no longer builds the mip levels for 450
  frames. Runs vary by about ±0.4 s, so call it "a little faster, maybe 0.2 s".
- The number of textures is unchanged (3,614): only the mip levels go.

## Look

Map `start`, isolated user folder, port 26098, 1280x720, new-player settings. Each of the three guns was raised in
two spots and the game was frozen for the shot. Before | after | difference x4 sheets are in `docs/gunnomip/`
(`compare_dookie.jpg`, `compare_drone.jpg`, `compare_greenjar.jpg`).

| gun | brightness of the gun area, before → after |
|---|---|
| dookie | 114.8 → 114.8, 98.3 → 98.2 |
| drone | 108.2 → 111.3 (a green dynamic light tints the whole "after" scene), 70.9 → 71.0 |
| green jar | 95.5 → 92.9 (a different animation frame inside the jar), 79.4 → 79.6 |

- The guns look the same: the same edges, sharpness and lighting, with no shimmer or fringe. View models are drawn
  at about 1:1, where the engine samples the full-size image whether or not mip levels exist.
- These shots are not a pixel-for-pixel test. The "before" run's window had no focus (20 fps, `cl_maxidlefps`) and
  the "after" run had (500 fps), so the freeze landed on a different animation frame. The pixel-matched test of
  this exact change is in the atlas report: its shaders put `nomipmaps` on the same three sets, and gun brightness
  matched within 0.3 levels in bright and dark spots.

### With `gl_picmip_other 1` (lowmem.cfg)

`lowmem.cfg` now switches on automatically for PCs with under 3 GB of video memory, so the same shots were taken
with `+gl_picmip_other 1` on the command line, two rounds of before and after:

| run | dookie bright / dark | drone bright / dark | green jar bright / dark |
|---|---|---|---|
| before, round 1 | 116.7 / 99.2 | 83.0 / 71.1 | 93.5 / 79.8 |
| after, round 1 | 153.7 / 99.2 | 83.0 / 71.2 | 93.2 / 79.8 |
| before, round 2 | 153.8 / 99.3 | 104.5 / 71.1 | 93.5 / 79.5 |
| after, round 2 | 153.7 / 99.2 | 108.9 / 71.1 | 93.5 / 79.8 |

- Picmip applies to the guns with and without the pack: the frames are drawn at half resolution in every shot.
  `nomipmaps` drops only the mipmap flag, and the picmip flag is set separately unless a shader says `nopicmip`
  (`model_shared_q3shader_loop.c.h`).
- The bright spot is not stable between runs: in round 1 the dookie gun was washed out in "after" only, and in
  round 2 it was washed out *without* the pack as well (153.8). The drone's bright spot moves the same way. Every
  dark-spot pair matches within 0.3.
- `docs/gunnomip/compare_lowmem.jpg`: round 2, dark spot, before | after, for dookie, drone and green jar.

## CI (`.github/workflows/build-zip.yml`)

- "Cache zz_gunnomip.pk3": key = base `bakersfield.pk3` sha256 + the builder's hash. The builder reads nothing else
  and needs no pip packages.
- "Build zz_gunnomip.pk3" runs on a cache miss. "Add overlay pk3s to the package" copies it in.
- "Check the package" fails if the pack is missing, if one of the three shader files is missing, if any shader in
  them lacks `nomipmaps`, or if `zz_gunframes.pk3` ships as well. Tested locally against the built pack (passes),
  a copy with one file removed and one `nomipmaps` deleted (both caught), a package without the pack (caught), and
  a package with both packs (caught).
- The header comment and release notes name the pack. YAML checked with js-yaml 4.1.0.

## Not done

- The server needs nothing (it loads no textures).
