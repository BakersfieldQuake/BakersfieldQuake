Architecture & Forensic Code Analysis

Root-Cause Deep Dive by Layer

Explore each layer of the stack. Click any finding to expand exact file/line citations, failure mechanics at 300–400 ms RTT, and the deployed remediation.

  • Root Cause (protocol.c:2758-2776, protocol.h:766): On every dropped server→client packet or packetlog overflow, DarkPlaces calls qsort(packetlogs, sizeof(*packetlogs), ENTITYFRAME5_MAXPACKETLOGS, packetlog5cmp) — passing nmemb (8 bytes) and size (64 slots) swapped! Worse, packetlog5cmp casts entityframe5_packetlog_t ** directly to entityframe5_packetlog_t *, comparing raw heap pointer bytes instead of packetnumber. Delta recovery ran out of order on every single lost packet.
  • Overflow Ceiling: ENTITYFRAME5_MAXPACKETLOGS = 64 allowed only 640 ms of unacked frames at 100 Hz — directly causing 16 and 10 full delta-state resets for Thailand player TruE even without [CAM], and 717 resets during a 10.5-minute match with [CAM].
  • Fix Deployed (source/darkplaces-netcode-highping.patch): Fixed qsort argument order (ENTITYFRAME5_MAXPACKETLOGS, sizeof(*packetlogs)), dereferenced *(const entityframe5_packetlog_t *const *) in packetlog5cmp, raised ENTITYFRAME5_MAXPACKETLOGS from 64 → 256 (3.55 s headroom at 72 Hz), and gated overflow console logging behind developer_networkentities >= 1 to prevent -condebug synchronous disk-flush stalls.
  • Root Cause (sv_user.c:620,666, sv_phys.c:2997-3001): sv_user.c:620 clamped every incoming move slice to min(0.1, sv_clmovement_inputtimeout.value) (100 ms) even though Zircon clients predict up to 250 ms. Any jitter/loss gap >100 ms permanently discarded movement. Worse, when a gap exceeded sv_clmovement_inputtimeout, SV_Physics ran synchronous movement using the stale host_client->cmd with //host_client->cmd.time = max(host_client->cmd.time, sv.time); commented out — so when delayed packets arrived, the server replayed async moves on top of stale sync drift (double-moving and snapping the player back 350–400 ms later).
  • Fix Deployed: Raised both moveframetime and clmovement_inputtimeout caps to min(0.25, sv_clmovement_inputtimeout.value) (matching Zircon's 250 ms client slice). During sync fallback (movesequence != 0), advanced host_client->cmd.time = min(sv.time, host_client->cmd.time + sv.frametime) — eliminating double-moves without creating a 400 ms post-timeout input blackout.
  • Root Cause (netconn.c:817): DarkPlaces' stop-and-wait reliable channel (window = 1 fragment, 1024 B) used a hardcoded 1.0 s retransmit timer. One lost reliable packet or ACK at 350–400 ms RTT froze all subsequent reliables for ~1.4 s.
  • Fix Deployed: Implemented RFC 6298 EWMA smoothed_rtt (α=0.125) and rtt_var (β=0.25) with Karn & Partridge Rules 1 & 2 (ignoring retransmitted ACKs and preserving backoff until a clean ACK completes), exposed via net_reliable_resend_timeout (0 = automatic RTT-adaptive, >0 = fixed override):
Formula: rto = bound(0.25, max(srtt + max(0.08, 4 * rtt_var), srtt * 1.4 + 0.05), 1.2)
  20 ms RTT (±5 ms)  → RTO 0.25 s  (4.0× faster than 1.0 s; 12.5× RTT margin → 0 spurious resends)
 150 ms RTT (±20 ms) → RTO 0.26 s  (+110 ms spike headroom)
 350 ms RTT (±40 ms) → RTO 0.54 s  (~1.85× faster recovery; +190 ms spike headroom)
 450 ms RTT (±60 ms) → RTO 0.69 s  (+240 ms spike headroom; backoff up to 1.5 s on bursts)
  • Root Cause (/opt/quake/demo_recorder.py): The headless [CAM] observer connected on 127.0.0.1 whenever ≥2 humans played, but (1) never sent clc_ackframe (triggering an EntityFrame5 overflow + full snapshot reset + qconsole.log flush roughly once every second — 717 times in a 10.5-min match!), (2) hardcoded unreliable send sequence to 0 so DarkPlaces' netconn.c:1336 dropped every unreliable packet after the first, and (3) set loopback rate 25000, starving demo detail.
  • Fix Deployed (demo_recorder.py): Added DP7 svc_entities (0x39, movesequence==0) parser guarded by exact EntityFrame5 terminator b"\x00\x80" + 2-consecutive-frame resync on >256-frame stalls; sends immediate clc_ackframe (0x32 + LE32 framenum) with a 32-bit masked monotonically incrementing unrel_send_seq; raised loopback rate to 150000. Result in A/B: 0 → 5,434 ACKed frames, 71 → 0 overflows, and complete 3.27 MB .dem recordings.
  • Why 100 Hz Hurt High-Ping Players: At sys_ticrate 0.01 (100 Hz) with old client rate 95000, DP7's net_usesizelimit 2 shrank max unreliable packet size to 922 B (and unreliable effects to 461 B), compressed the client 2-state lerp window to just 10.0 ms, and exacerbated KVM CPU contention (8–18% host CPU steal produced 22.8 ms idle stalls — 2.28× a full tick!).
  • Fix Deployed (server_vps.cfg + netfix-rt.conf):
    • Set sys_ticrate 0.0138889 (72 Hz — raises packet budget to 1400 B, widens lerp to 13.89 ms, cuts server CPU by nearly half).
    • Aligned server physics with Zircon client cl_input_pmove.c.h: sv_gameplayfix_downtracesupportsongroundflag 1, sv_wallfriction 0, sv_jumpstep 1, sv_clmovement_inputtimeout 0.25, sv_maxvelocity 6500, sv_maxrate 1000000.
    • Installed systemd drop-in /etc/systemd/system/quake-bakersfield.service.d/netfix-rt.conf: CPUSchedulingPolicy=rr, CPUSchedulingPriority=10, IOSchedulingClass=best-effort, IOSchedulingPriority=0, TimerSlackNSec=50000 (50 µs timer precision, preempting non-RT co-located services like Node/Docker/Netdata).
  • Pushback Rubber-Banding Eliminated: q15_config_coop.cfg enabled pushback 1, mutating self.velocity server-side on every RL/LG/SSG/GL/SNG/Axe/DN3/Cyrax shot (10×/sec on LG!). Client PMove never predicts weapon recoil pushback, snapping the shooter every shot at 350 ms RTT. Disabled globally (pushback 0) and gated W_FireAxe & cyrax.qc recoil behind autocvar_pushback != 0.
  • 48-Frame Server-Side Lag Compensation (antilag.qc / antilag_defs.qc): Records a 48-frame circular origin buffer (~667 ms at 72 Hz) per player in StartFrame(). On hitscan/melee fire, reads engine-native .float ping (DP_SV_PING in ms, supported identically on VPS DarkPlaces and Zircon), interpolates targets back by bound(0, ping * 0.001, sv_antilag_maxping * 0.001) (default sv_antilag 1, sv_antilag_maxping 450), skips dead/non-solid/teleported (>256 u) targets, brackets strictly around traceline() via setorigin() (no SV_TouchLinks), and restores before damage/knockback. Wired into all 9 weapon fire sites (W_FireAxe, FireBullets, all 3 LightningDamage traces, DN3SG_FirePellets, M4, Garand, Sniper, Hammer, Cyrax).
  • Reliable Channel Saturation Fixed: Previously, hitsound.qc and proj_collide.qc fired reliable stuffcmd(attacker, "playvol misc/mmhit*...\n") up to 8.3×/sec — exceeding DP7's ~2.8 reliable pkts/sec ceiling at 350 ms RTT and stalling damage flashes, camera switches, and centerprints.
  • Fix Deployed: Replaced all hitsound stuffcmd calls with HitSound_Emit(attacker, 1..6) writing unreliable stat 158 (bm_st_hitsnd = seq * 8 + tier, wrapping seq at 31 so value stays ≤ 255 → compact 3-byte svc_updatestatubyte). 5 Subtle Bugs Caught & Fixed in Independent Pre-Deploy Review (#27, #28, #31, #32, #35)

Every patch and config underwent an independent adversarial code audit before staging or VPS rollout — preventing 5 real production regressions:

BUG #1Karn & Partridge Rule 2 RTO Livelock

In both C patches (netconn.c), reliable_resends was cleared unconditionally after retransmitted ACKs and new sends. If a player's RTT jumped from 200→400 ms, every reliable packet would time out spuriously forever with smoothed_rtt frozen at 200 ms.

FIX: Reset reliable_resends = 0 strictly inside if (!conn->reliable_resent) on clean ACKs only.

BUG #2cl_smooth Leaking onto Vehicle/Killcam Views

BakersfieldQuake uses p.clientcamera (cl.viewentity != cl.playerentity) for vehicles, tanks, Rocket Rider, and killcam. Player pred_error_offset would leak onto camera entities or collide with PRED_ZIRCON_MOVE_2.

FIX: Clear pred_error_offset whenever viewentity != playerentity, demoplayback, or PRED_ZIRCON_MOVE_2.

BUG #3Antilag Mid-Rewind Damage & Teleport Hazard

FireBullets and DN3SG_FirePellets initially wrapped the entire pellet loop in Antilag_Rewind/Restore. Calling PC_TraceIntercept / AddMultiDamage mid-rewind could detonate projectiles or kill/respawn a player before Antilag_Restore() snapped them back.

FIX: Bracket Antilag_Rewind/Restore strictly around traceline() per pellet; run all damage on restored positions.

BUG #4[CAM] False-Positive 0x39 Scan & >256-Frame Wedge
